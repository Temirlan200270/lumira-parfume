# Админка

Интерфейс для стойки: `/admin`. Шапка магазина, футер и нижнее меню на этом пути скрыты (`StoreChrome`). Свой хедер: логотип, ссылка на витрину, выход.

Код: `src/app/admin/`. Права **не** зашиты в UI — только `requireAdminEmail` + список `ADMIN_EMAILS`.

## Вход

Email и пароль через Supabase Auth. Публичная регистрация в проекте должна быть выключена: заводят аккаунты вручную.

Пускает только адрес из `ADMIN_EMAILS` (через запятую в `.env`). Чужой залогиненный пользователь видит «Нет доступа».

Без `SUPABASE_SECRET_KEY` / service role страница просит заполнить `.env.local`.

## Две вкладки

По умолчанию открываются **Заказы**. Витрина — `?pane=vitrina`.

Макет узкий (`max-w-2xl`), кнопки 44px, на телефоне шторки снизу, на десктопе окно по центру (`AdminSheet`).

## Заказы

Очередь из таблицы `orders` (последние 100). Статусы на русском:

| Статус | Где |
|--------|-----|
| Новый, Подтверждён | **В работе** |
| Оплачен, Выдан, Отмена | **Архив** |

В карточке: номер `LM-…`, время по `Asia/Almaty` («сегодня 14:22»), имя, телефон (на мобиле — `tel:`), состав со снимком цен, итог, «Kaspi после подтверждения».

WhatsApp уходит **на телефон клиента**, текст собирается на серверных суммах.

Чипы статуса жмутся сразу, без отдельной кнопки «Сохранить». Ошибка откатается тостом.

Если `telegram_sent === false` — строка «уведомление не дошло» (заказ с сайта, пуш в Telegram не прошёл). Заказы из админки пишутся с `telegram_sent: true` и **в Telegram не шлются** — стойка и так видит карточку.

### Новый заказ

Кнопка на вкладке заказов. Шторка: имя, телефон (маска +7), поиск аромата по каталогу, объём 5/10/20, количество, итог.

Для стойки **не** требуется «на сайте» и «в наличии» — можно продать скрытый или закончившийся оффер (`calculateAdminOrder`).

После создания карточка сразу во «В работе».

## Витрина

Список **офферов** (разлив и распив одного имени — две строки). Поиск по бренду и названию, табы Все / Разлив / Распив.

В строке: фото, цена ₸/мл (автосейв по blur), серые 5/10/20, тумблеры **В наличии** и **На сайте**, удаление.

- **В наличии** — `offers.is_in_stock`: на витрине бейдж «нет в наличии», в корзину с сайта не кладётся.
- **На сайте** — `offers.is_active`: строка пропадает из публичного каталога (нужен ещё активный product).

Тост после сейва. Кнопки «Сохранить» нет.

### Добавить позицию

Кнопка на вкладке витрины. Одно окно: фото (JPEG/PNG/WebP до 5 МБ), бренд, название, пол, формат, цена за мл.

Позиция сразу в списке и на сайте (`is_active` / `is_in_stock` = true). Если такое имя уже есть — второй формат цепляется к той же карточке. Дубль того же формата отклоняется.

Фото в bucket `product-images`. Без фото карточка уйдёт с плейсхолдером.

Пол по умолчанию унисекс, формат — разлив. Описание и ноты из этой формы не задаются.

### Удалить с сайта

Подтверждение в шторке. Старые заказы не трогает (в заказе JSON-снимок). Если это последний оффер товара — удаляется `products` (офферы каскадом).

## Чего админка не делает

Не считает выручку, не печатает чек, не принимает Kaspi сама, не правит юридические тексты, не шлёт Telegram по заказам со стойки. Состав витрины из админки **не** попадает автоматически в `inventory.ts` — см. предупреждение в [DATA.md](DATA.md).
